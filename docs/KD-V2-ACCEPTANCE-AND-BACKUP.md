# КД v2 — приёмка этапов 0–1 и резервное копирование

## Контрольный шлюз перед изменением рабочей базы

GitHub содержит код, но не резервную копию фактических данных. Снимок публичного каталога или тарифов не заменяет бэкап базы. Не передавать в чат, GitHub или артефакты CI дампы, пароли, токены, персональные данные и действующие закупочные цены.

Проверить в панели хостинга Timeweb (либо у администратора фактической рабочей БД):
1. Определить рабочую базу приложения по настройкам хостинга, не публикуя строку подключения.
2. Сделать актуальную полную резервную копию структуры и данных этой БД. Хранить в закрытом хранилище с контролем доступа.
3. Убедиться, что копия читается, записать дату/время, размер и контрольную сумму SHA-256, если доступно.
4. Восстановить копию в отдельную тестовую БД с отдельным пользователем; не восстанавливать поверх рабочей БД. Отключить исходящие уведомления/интеграции тестового окружения.
5. Сравнить перечень таблиц и количества записей с исходной копией; проверить чтение нескольких записей и связанных расчётов в изолированной среде. Не передавать их содержимое в репозиторий.
6. Зафиксировать только итог проверки, дату, ответственное лицо и место хранения без секретов.

По исходному timeweb/backend/surveyor.php отдельно проверить наличие и согласованность surveyor_users, surveyor_sessions, surveyor_clients, surveyor_orders (включая configuration_json), surveyor_owner_costs. Это минимальный набор, а не перечень всей базы. Данные, существующие только в IndexedDB на телефонах и ещё не синхронизированные с сервером, отдельно учитывать перед миграцией: проверить наличие очереди/конфликтов и предусмотреть локальный экспорт или безопасную синхронизацию. Не считать серверный бэкап копией несинхронизированных данных.

**До подтверждения восстановления не запускать миграции, не изменять production и не переключать рабочую версию.** В настоящее время разрешены только локальная разработка и тесты на синтетических данных.

## Мобильная приёмка оболочки

Автономный HTML-макет подходит только для проверки дизайна, не для проверки настоящих расчётов. Для полной приёмки нужен отдельный безопасный тестовый origin без рабочей БД. GitHub Pages разных репозиториев одного владельца на *.github.io может иметь общий origin, поэтому одного нового пути недостаточно. Для нового HTTPS-адреса — отдельный hostname и проверка отсутствия рабочего API; либо локальный сервер на самом устройстве. Не использовать текущий DEV или основной домен для перезаписи. Не вводить данные реальных клиентов.

### Действия собственника на телефоне
- Открыть макет/тестовую сборку, проверить читаемость на обычной яркости и отсутствие горизонтальной прокрутки.
- Переключить КД Управление → КД Замерщик; оценить плитки, нижнее меню, размеры кнопок.
- Открыть каталог: кованые ворота Арт., кованые заборы Арт., каркасы, откатные ворота, евроштакетник, профнастил, навесы.
- Переключить светлую/тёмную тему и проверить читаемость. В полном PWA повторить на клиентах, замерах, схеме, экономике и 3D.
- Только в полном PWA: создать тестовый объект, открыть действующий расчёт, проверить возврат и сохранение при перезапуске, в том числе офлайн.
- Сообщить «дизайн принят» или приложить скриншоты неудобных мест. Для приёмки PWA отдельно подтвердить фактическое выполнение сценариев.

### Критерии
Ширина экрана 320–430 CSS px и десктоп; минимум 44 px для основных кнопок оболочки; читаемые состояния, доступные имена кнопок, видимый фокус, одна навигация; нет реальных записей и неожиданных сетевых операций. Не считать скриншоты Chromium заменой проверки на реальном Android.

## Текущие ограничения
Отдельная рабочая БД и восстановление не подтверждены, отдельный HTTPS-host не создан. GitHub-интеграция не умеет создавать репозитории и настраивать Pages. Текущая сборка локальная, рабочий сайт не изменён. Для будущих этапов новые калькуляторы кованых заборов Арт. и профнастила требуют утверждённых конструктивных правил и тарифов; не использовать вымышленные цены.
