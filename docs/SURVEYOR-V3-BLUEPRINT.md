# КД Замерщик 3.0 — архитектура и UX

Дата: 2026-10-08
Рабочая ветка: `feature/kd-surveyor-v3-redesign` (ответвление от DEV).
Статус: проектная спецификация; рабочие маршруты и данные не изменены.

## 1. Цель и основное правило
Замерщик без обучения должен выполнить типовой сценарий:
**ввести телефон и адрес → выбрать изделие → показать настоящую фотографию/визуал →
ввести размеры → показать полную цену клиенту → добавить результат в заказ → завершить замер.**

Внутренняя схема объекта — вспомогательный инструмент, а не обязательная преграда
между созданием выезда и расчётом. До договора ФИО клиента не запрашивать.

## 2. Критика UX 2.x и сохранение наработок
Проблема — длинный процесс: новый замер, типы работ, сохранение состава,
отдельное создание схемы, добавление множества элементов, и только после этого
доступ к расчётам. По скриншотам виден конфликт «Элементов: 0» с заполненным
списком и возможные дубли элементов. Не считать эти баги диагностированными без теста.
Сохраняются: авторизация сотрудников, IndexedDB, офлайн-очередь, синхронизация,
существующие движки расчётов, модели Арт. и фотографии, реальные варианты ферм
навеса и изображения ограждений. Новая система использует существующие движки,
но получает единый упрощённый режим замерщика.

## 3. Главное меню — минимализм
Постоянная нижняя навигация: «Замеры» / «Каталог» / «Ещё».
На «Замерах»: поиск по телефону, адресу или номеру; «+ Новый замер»;
список выездов с адресом, ценой, количеством позиций и состоянием синхронизации.
«Каталог» позволяет показывать товары и считать до создания карточки;
сохранение варианта вызывает короткую форму телефона/адреса и прикрепляет расчёт.
«Ещё»: синхронизация, база для офлайна, профиль; управление пользователями
только для собственника.

## 4. Создание замера
Модальное окно/полноэкранный экран: телефон (маска +7), населённый пункт/полный
адрес с сохранённой офлайн-базой, заметка необязательна. Кнопка «Начать замер».
Ни имя, ни вид работ, ни схема не нужны. После сохранения — немедленный переход
на главный экран этого замера. Локальное сохранение перед переходом обязательно.

## 5. Экран карточки — единый центр работы
Заголовок: «← Замеры | ЗМ-xxxx», адрес в одну строку, иконка редактирования.
Вверху компактный индикатор «На устройстве / Ожидает синхронизации / Сохранено».
Ниже 3 крупные карточки:
- «Ворота и калитки» — фото модели / «Выбрать ворота».
- «Забор» — реальное изображение заполнения / «Рассчитать забор».
- «Навес» — рендер/визуал фермы / «Рассчитать навес».

Нажатие сразу открывает соответствующий инструмент. Никакого обязательного
шага «Выберите, что замеряем» или «Создайте схему» нет.
Ниже — сохранённые позиции и альтернативы (показывать фото, описание и цену),
строка доставки (только один раз) и ИТОГО. Закреплённая снизу панель с итогом
и кнопкой «Показать клиенту». Вторичные функции: «Схема расположения»,
«Фото объекта», «Условия монтажа», «Завершить замер».

## 6. Три специализированных сценария
### 6.1. Ворота / калитка
Сначала визуальный каталог Арт. с реальными изображениями, фильтрами и
наглядной ценой «от» (только если расчёт доступен). Затем детальная карточка:
фото-листалка, выбор модели, ворота/калитка (вместе, отдельно или встроенная),
ширина/высота, готовые/новые столбы, тип столба и количество, связка, монтаж,
доставка в итоговом заказе. При вводе — моментальная **цена для клиента**.
Крупные кнопки «Показать клиенту», «Добавить в замер».
Полные расчётные формулы берутся из DEV; не дублировать коэффициенты в V3.
Возможно хранить 2–3 альтернативных артикула в одной группе для клиента;
в сумму идёт ТОЛЬКО выбранная альтернатива.

### 6.2. Забор
Сначала три крупные фото-опции: вертикальный односторонний, вертикальный
двусторонний (шахматка), горизонтальный, затем длины, высота, углы,
количество линий/участков (до четырёх, расширение по необходимости),
шаг штакетника, существующие/новые столбы, монтаж. Пролёты ≤ 2,5 м,
переиспользование общих столбов. Калькулятор строит понятную схему и цену
одновременно. Сохранение возвращает в карточку замера.
Геометрия не может считать одни и те же физические столбы дважды.

### 6.3. Навес
Сразу крупные понятные картинки типов ферм без карусели и горизонтальной
прокрутки; размеры «между крайними столбами» и длина; вариант покрытия
(поликарбонат, профнастил, без покрытия); новые/готовые столбы и балки;
показ размеров фермы по наружным краям, длины дуги, покрытия и визуализации;
пересчёт цены при каждом изменении. Нельзя заново сочинять формулы:
переиспользуем реальный DEV engine и визуал. Сохранение — в карточку.

## 7. Два слоя интерфейса
«Замерщик»: контакт клиента, размеры, условия, фотографии и визуализация,
все выбранные варианты, публичная цена; кнопки редактирования.
«Показать клиенту»: полноэкранные реальные фото/визуал, выбранные размеры,
понятная комплектация, цена и общая стоимость, без редактируемых служебных полей.
Режим замерщика не получает от сервера себестоимость, зарплату, маржу, закупку,
коэффициенты наценки и скрытые административные поля. CSS-скрытие
конфиденциальных данных недостаточно. Служебные расчёты выполняет закрытый
сервер либо строго разделённый клиентский engine без секретов.

## 8. Схема — только когда полезна
Схема для взаимного расположения ворот, калитки, заборов и общих столбов.
Это не второй независимый список изделий. Объект в схеме ссылается на
соответствующую сохранённую позицию; изменение размеров синхронизируется
с калькулятором и валидируется. Навес обычно отдельная зона плана.
Стартовый чертёж автоматически составляется из выбранных изделий;
замерщик может поправить порядок и существующие столбы.
Подсказки на обычном русском: «Добавить пролёт слева», «Есть столбы»,
«Калитка справа от ворот». Никаких микроскопических плюсов
и повторных длинных списков на основном экране.

## 9. Единая модель данных (логическая)
Survey {id, clientPhone, address, note, status, createdBy, sync, sections,
sitePlan?, sitePhotos[], conditions, delivery, quoteRevision, quoteStatus}
Section {id, kind:gates|fence|canopy, label, geometryRefs[], optionGroupId?,
chosenOptionId?, options[]}
Option {id, calcKind, engineVersion, inputs, photoOrVisualRef, dimensions,
publicBreakdown, publicTotal, chosen, createdAt, updatedAt}
SitePost {id, existing:boolean, profile, location, referencedBy:[]}
Quote {surveyId, selectedOptionsOnly, deliveryExactlyOnce, adjustments,
publicTotal, currency:RUB, snapshotAt, priceVersion}
- Сохранение вариантов не дублирует блок или стоимость.
- Миграция старого `configuration.calculations` и `configuration.sitePlan`
  идемпотентна, со старой структурой только для чтения до тестов.
- Изменение прайса не меняет уже согласованную цену автоматически:
  явно предлагать «Пересчитать по новым ценам».
- Каждое изменение autosave локально, без молчаливой потери данных.

## 10. Деньги — где чаще всего ошибаются
Одна доставка на весь заказ, обычно 90 ₽/км от Мелеуза (Мелеуз бесплатно),
а не по одной доставке в каждом изделии.
Нужно разделить составные итоги расчётов на изделия/столбы/монтаж/доставку.
При общих столбах — опора имеет единый ID и участвует в цене один раз;
перерасчёт влияет на спецификацию. Стоимость нескольких альтернатив не суммировать.
Реальные цены берутся из текущих активных DEV данных, а не из заглушек.
Перед передачей расчёта проверить корректность итоговой суммы.

## 11. Офлайн и синхронизация
PWA на телефоне; сначала скачать минимально необходимую версию калькуляторов,
цен, фото каталога, изображений ограждений, иконок ферм и базу населённых пунктов.
Обновлять базу по версии и вручную по кнопке, без повторного скачивания на каждом
старте. Проверить фактическую работоспособность всех 3 расчётов без интернета.
Состояния: «Сохранено на телефоне», «Ожидает отправки», «На сервере»,
«Конфликт — требуется решение». Индикатор «Онлайн» не означает «Синхронизировано».
Изменения нескольких устройств — с ревизиями, а не «последний затёр всё».
Показывать ошибки отсутствующих ресурсов; не обещать полностью готовый офлайн
без соответствующего интеграционного теста.

## 12. Миграция и удаление мусора
Старые маршруты и PWA не удалять до резервной копии и переноса всех данных.
Особенно важны черновики «На устройстве» — они могут находиться только в памяти
браузера текущего устройства. Экспорт/перенос и сверка количества записей.
Сделать старую оболочку доступной только для чтения, затем перевести пользователей
на V3. После контрольного периода удалять только подтверждённо неиспользуемые
пути, старые файлы и устаревшие Service Worker scopes; не удалять действующие
калькуляторы и изображения. Карта маршрутов, безопасные редиректы, проверки PWA.
Production и публичный каталог НЕ менять до отдельного разрешения.

## 13. План исполнения с приёмкой
1. **UX 3.0 / Навигация**: новый стартовый экран, создание замера, главный экран
   с 3 карточками и итогом. Отдельная ветка от DEV; существующие расчёты и данные
   не изменяем. Тест на мобильной ширине 360–430px.
2. **Ворота**: реальные фото Арт. → настройки → достоверная цена → запись
   в ту же карточку → редактирование без дублей.
3. **Забор**: реальные варианты → размеры/углы/столбы → визуал/цена →
   сохранить и редактировать.
4. **Навес**: фермы/типы покрытий → визуал/цена → сохранить/редактировать.
5. **Общий заказ**: альтернативы, однократная доставка, общие столбы, итог,
   клиентский режим и автосохранение.
6. **Схема и чек-лист выезда**: по желанию, синхронизированы с позициями,
   фото (до 10), адрес, условия монтажа.
7. **Офлайн/сервер/безопасность/миграция**: 3 сквозных офлайн-теста, сохранение
   ценовых снимков, разграничение ролей, перенос старых данных.
8. **Очистка**: инвентаризация, резервные копии, удаление только подтверждённых
   неиспользуемых компонентов после завершённой миграции.

## 14. Обязательные сквозные проверки
- Новый замер → телефон + адрес → ворота Арт. с фото → изменить размер →
  увидеть клиентскую цену → добавить → повторно открыть → без дубля.
- В одном заказе ворота + забор + навес; итог = выбранные изделия +
  доставка один раз, без двойного счёта общих столбов.
- Два варианта ворот в одном сравнении: цена суммы содержит только выбранный.
- Сохранение, закрытие браузера, открытие без интернета — всё сохранено,
  все три калькулятора действительно работают и отдают цены.
- «Показать клиенту» никогда не показывает себестоимость и прибыль,
  недоступны они и в сетевых ответах для роли замерщика.
- Пустая схема и удаление элементов не создают повторов; счётчик совпадает
  с числом элементов. Нажатия достаточного размера, без горизонтального скролла.
- Очередь офлайн синхронизируется без исчезновения фото/замеров/вариантов.
