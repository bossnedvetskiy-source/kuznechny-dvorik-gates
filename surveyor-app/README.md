# КД Замерщик — Этап 1

Отдельный mobile-first PWA для выездного замерщика. Клиентский сайт не используется как интерфейс приложения.

## Что работает

- серверная авторизация для рабочей версии;
- существующий основной admin-логин получает роль собственника;
- отдельные сотрудники-замерщики с собственными логинами и паролями;
- собственник может добавлять, редактировать и отключать сотрудников;
- отключение сотрудника отзывает его серверные сессии;
- клиенты;
- один замер может включать одновременно `Ворота / калитка`, `Забор`, `Навес`;
- локальное хранение IndexedDB;
- PWA и Service Worker;
- офлайн-вход на уже авторизованном устройстве;
- очередь несинхронизированных изменений;
- серверная синхронизация клиентов и замеров;
- сервер выдаёт уникальный номер заказа после первой синхронизации;
- ревизии и защита от молчаливого перезаписывания конфликтующих изменений;
- собственник видит все серверные замеры, замерщик — свои;
- архивирование заказа доступно только собственнику.

## DEV-превью

Обычный GitHub Pages DEV работает локально и не пишет данные в рабочую БД.

Тестовые учётные записи DEV:
- `admin / 1234`
- `zamer / 1234`

Параметр `?server=1` предусмотрен только для проверки серверного API после его отдельной публикации.

## Рабочая серверная схема

API: `/api/surveyor/*`

Основные таблицы:
- `surveyor_users`
- `surveyor_sessions`
- `surveyor_clients`
- `surveyor_orders`

Таблицы создаются безопасно через `CREATE TABLE IF NOT EXISTS` при первом обращении API; полный DDL также хранится в `timeweb/backend/schema.mysql.sql`.

## Следующий этап

Визуальный конструктор линии объекта:

`столб → пролёт → ворота → пролёт → калитка → забор → ...`

Каждый элемент будет отдельным редактируемым объектом, а сохранение продолжит использовать текущую схему офлайн + серверной синхронизации.
