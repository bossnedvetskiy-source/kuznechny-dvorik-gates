# Изолированная синхронизация замерщика (только DEV)

**Статус:** сервер реализован и проверяется в CI, но не размещён. Пока отдельный хост не настроен, DEV работает офлайн и не отправляет данные куда-либо. Production и его база не используются.

## Размещение на отдельном тестовом сервере

Требуется отдельный сервер/VPS или контейнер для Node.js 22, постоянный приватный том для данных, HTTPS reverse proxy и отдельный домен, **не** `kuzdvor.tw1.ru`. Не размещать сервер на GitHub Pages; GitHub Pages обслуживает только статические файлы.

```sh
# На ИЗОЛИРОВАННОМ сервере, вне каталога рабочего сайта:
export DEV_STAGING_CONFIRMED=1
export NODE_ENV=production
export DEV_OWNER_PASSWORD='уникальный-сложный-пароль-руководителя'
export DEV_SURVEYOR_PASSWORD='другой-уникальный-сложный-пароль-замерщика'
export DATA_FILE=/srv/kd-dev-sync-private/data.json
export DEV_ORIGIN=https://bossnedvetskiy-source.github.io
export PORT=8787
node dev-sync/server.mjs
```

Прокси HTTPS должен пересылать `/api/surveyor/login` и `/api/surveyor/sync` на `127.0.0.1:8787`. Закрыть прямой внешний доступ к порту; резервировать приватный файл данных; ограничить попытки входа на уровне proxy/WAF. Не копировать рабочую базу клиентов в DEV.

После настройки **указать URL только тестового API** в GitHub Actions variable `DEV_SURVEYOR_API_URL`, например `https://dev-sync.example.org/api/surveyor` (пример, не рабочий адрес), и вручную запустить workflow **Deploy protected dev site**. Значение переменной — публичный URL, **не пароль**.

Без этой переменной DEV остаётся локальным. Параметр `?server=1` больше не включает рабочий API. Старые локальные записи сохраняются, но автоматически становятся доступными на другом устройстве только после авторизации на выделенном DEV-сервере и успешной синхронизации.

## Роли и гарантии

- Учётная запись `admin` видит все DEV-замеры; `zamer` — только свои. Пароли отдельные от production.
- Offline: запись сначала сохраняется в IndexedDB телефона, после связи отправляется серверу.
- Повторная отправка нового заказа с тем же ID и исходным временем не создаёт дубль.
- Для изменённой версии действует счётчик ревизий; конфликт не перезаписывает изменения молча.
- Телефон и адрес не обязательны. Состав расчётов, изображения-каталожные ссылки и ТЗ хранятся в конфигурации (до 120 КБ на замер).
- Пока пилотный JSON-файловый сервер не рассчитан на большую промышленную нагрузку; перед полномасштабным внедрением перенести хранение в отдельную транзакционную БД, добавить мониторинг и политики резервирования.
- Время, дата, роли и пользовательские разрешения должны перепроверяться на сервере, а не только в интерфейсе. Для настоящего промышленного запуска нужна независимая проверка безопасности.

## Автотест

```sh
node --test dev-sync/test.mjs
```

Тест проверяет вход, защиту от чужих источников, сохранение необязательных полей, просмотр руководителем, повторную отправку без дублей, конфликт ревизий, запрет изменения чужого замера и запись на диск.
