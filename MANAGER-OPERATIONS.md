КД Менеджер: обновление и проверка

Исправления предназначены для текущего Timeweb PHP/MySQL backend. Публикуется пакет, созданный `npm run build` и `node scripts/build-timeweb.mjs`; в нём теперь есть manager-app.js и новые файлы backend. Отдельная публикация одного manager.html недостаточна.

Перед выпуском сохранить резервную копию базы. При первом входе сервер автоматически добавляет роль/признак отключения сотрудника, поля результата замера, исполнителя, часового пояса и ревизии. Существующие учётные записи сохраняют роль администратора, существующие заявки не переназначаются. Для обновления нужны права CREATE/ALTER; если у рабочего пользователя MySQL их нет, выполнить обновление схемы из CLI с учётной записью, имеющей эти права. Новые поля и таблицы можно оставить при откате файлов приложения.

После выпуска администратор открывает «Сотрудники и доступ» в приложении и создаёт отдельные логины. Менеджер работает со всеми заявками, но не меняет каталог/цены. Замерщик видит только назначенные ему заявки. Назначение выбирается в карточке заявки. Отключение сотрудника завершает его серверные сессии и удаляет push-подписки. Офлайн-копия на его устройстве автоматически не отзывается без связи: срок доступа — 24 часа с последней успешной онлайн-проверки. Пароль офлайн-копии хранится только в памяти приложения, данные в localStorage зашифрованы AES-GCM. Выход удаляет копию. При истёкшей сессии шифрованные черновики можно восстановить после повторного входа тем же сотрудником, используя прежний офлайн-пароль.

Для напоминаний и отправки push с повторами установить запуск каждую минуту от пользователя сайта. Пример для расположения из текущего .htaccess (проверить реальные пути на хостинге):

```cron
* * * * * KD_ACCOUNT_DIR=/home/c/cp59598/kuznechny-dvorik-gates /usr/bin/php /home/c/cp59598/kuznechny-dvorik-gates/public_html/backend/process-manager-push.php >> /home/c/cp59598/kuznechny-dvorik-gates/manager-push-worker.log 2>&1
```

Перед добавлением cron выполнить эту команду один раз без перенаправления и проверить результат. Путь к PHP может отличаться. Worker использует существующую закрытую конфигурацию сайта; секреты не передаются через командную строку. Напоминание формируется за час до назначенного замера. Перенесённые/отменённые назначения проверяются повторно непосредственно перед отправкой. Временные ошибки повторяются до шести попыток; обработанные задания удаляются через семь дней.

До установки cron уведомления о новых заявках сохраняют прежний способ отправки в завершении PHP-запроса. Как только worker регулярно работает, запрос клиента только ставит уведомление в очередь. Если heartbeat worker отсутствует более трёх минут, включается резервная отправка для новых заявок. Напоминания требуют работающего cron; сам файл приложения не запускает серверное расписание.

Проверки:

```bash
node scripts/test-manager-logic.mjs
npx playwright test tests/manager-app.spec.js
php -l timeweb/local-api.php
php -l timeweb/backend/manager-workflow.php
php -l timeweb/backend/manager-push.php
```

Workflow `Manager application checks` дополнительно проверяет сохранение и конфликты на отдельной MySQL 8, доступ замерщика, откат транзакции, ограничения push endpoint и шифрование Web Push с независимым расшифрованием получателем. Тестовая база не связана с production.

Проверить на телефоне: вход с неверным паролем; заметку после изменения даты; ввод после 15 секунд и после звонка; старую заявку за пределами первой сотни; этап «Производство»; одновременное изменение двумя сотрудниками; результат замера и фото; повторный запуск без сети после включения офлайн-доступа; восстановление черновика после возвращения связи; выход с очисткой; push-тест именно этого телефона; напоминание с работающим cron. Для iOS установка и push зависят от версии системы и запуска с главного экрана — проверить на используемых устройствах.

Результат замера хранит размеры, диагонали, перепад уровня, столбы, направление открывания, препятствия, заметки, описание эскиза и до четырёх сжатых JPEG. Он доступен в карточке сотрудникам с правами на заявку, а каждое сохранение попадает в серверную историю. Это не генератор производственных чертежей: конструктивные допуски, автоматическая проверка геометрии и экспорт подписанного акта требуют отдельной спецификации изделий.

Фотографии в этом выпуске хранятся в JSON результата замера и истории. При большом объёме базы стоит вынести их в закрытое файловое хранилище и загружать карточки с фотографиями по требованию. Размер отдельного сохранения ограничен 2 МБ; браузер предупреждает, если не удалось записать шифрованную копию из-за квоты устройства. Копии и журнал содержат персональные данные, поэтому срок их хранения на сервере следует задать в правилах эксплуатации.
